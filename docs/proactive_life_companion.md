# 主动生活对话设计草案

## 当前后续改动清单

当前待继续完成的功能仅包含以下两项。已经落地的关系身份、回复调度和状态观测基础能力不重复计入本清单。

- **主动私聊陪伴**：只面向稳定关系身份系统认证的“哥哥”私聊。每天生成一致的生活轨迹，并在早间、日间和夜间安排候选开口时间；到点后可以发送、延后或跳过，不把候选数量当作强制发送额度。私聊被动回复频率与主动开口调度保持独立。
- **自适应表情行为**：提高轻松私聊中的表情包使用率，同时根据语境动态调整。加入私聊与群聊分离的基础倾向、情绪场景加权、连续发送冷却、短期重复抑制和发送结果观测；不采用每条回复固定附图，也不把候选数量误作发送概率。

两项功能都必须复用稳定关系身份与部署配置，源码和通用插件配置中不得写入真实 QQ 号。

## 目标

让角色像有自己生活节奏的人一样，在合适的时间主动找指定关系用户聊天，而不是按固定文案发送提醒。

该能力不保存真实 QQ 号。目标用户由现有的稳定关系身份系统解析，插件或调度器只使用关系角色标识。

## 每日节奏

- 早间窗口为 `07:00-10:00`，每天最多触发一次。当天生成具体时间，并结合生活轨迹选择早安、赖床、早起或冷笑话等自然开场。
- 日间在避开深夜的范围内，预先生成并分散安排 `3-5` 个候选话题时间点，而不是每隔若干分钟独立抽概率。
- 夜间窗口为 `23:00-02:00`，按一个跨日窗口处理，每个生活日最多触发一次。内容可为晚安、熬夜中的随口聊天或当天收尾。
- 所有时间点都是候选事件。到点后仍需根据最近聊天、冷却时间、在线状态、角色情绪和当天已发送次数决定发送、延后或跳过。

## 生活轨迹

每天生成一份可查看的虚构生活轨迹，例如上课、吃饭、逛街、图书馆、出门玩或在家休息。轨迹必须保持前后时间一致，不能同时出现在冲突地点。

每个事件至少记录：

- 生活日与开始、结束时间
- 活动与粗粒度地点
- 当时情绪和可用于聊天的素材
- 来源标记 `assistant_generated`
- 候选触发时间和触发状态
- 实际发送时间，或未发送原因

当天轨迹属于短期日记，不自动视为永久事实。只有被反复提及、与用户共同发生、形成约定，或被用户明确确认的内容，才由后续记忆整理流程提升为长期记忆。

## 调度流程

每日生活生成器先产生当天轨迹和候选时间点。调度器到点唤醒主动对话事件，并进行静默时段、冷却、重复和最近会话检查。通过检查后只向 Planner 提供“现在发生了什么”和“为什么想开口”，最终由 Planner 决定是否回复及如何表达。

事件状态使用 `planned`、`due`、`deferred`、`sent`、`skipped`、`failed`。排队成功不等于已发送，只有消息通道确认成功后才能进入 `sent`。

跨午夜的夜间窗口按窗口起始日期归属，避免午夜前后各触发一次。静默策略应允许仪式型窗口覆盖普通静默时段，而不是用单一静默区间直接拦截所有事件。

## 人设与关系边界

- 内容遵循全局人格，不在插件内复制一套人设。
- 对“哥哥”的称呼和行为只由稳定关系身份系统授权，不依赖昵称或提示词猜测。
- 关系语义是兄妹，不引入恋爱等级、暧昧后缀、亲吻或恋人模板。
- 主动消息可以被取消、跳过或延后；不以完成发送配额为目标。
- 生活轨迹可以虚构，但共同经历、用户现实信息和承诺不得虚构。

## 可观测性

WebUI 应能看到当天生活轨迹、候选时间点、当前状态、最近一次主动消息、跳过原因和下一次候选唤醒时间。用户可以暂停当天主动消息、调整窗口、删除或纠正一条轨迹。

## 候选插件 `life-frequency`

`org.orge-8.life-frequency` 与本项目的生活层目标高度相关。它已经包含持续活动、情绪体力、睡眠、生理节奏、近期经历、关系熟悉度、主动开口素材和回复频率调节，可作为生活状态层的实现基础。

它不只是日程或日记插件：生活状态会直接乘到宿主回复频率上，睡眠与静默时段还会形成硬静默。因此不能在生产环境直接启用全部能力。应先用 `simulation.dry_run = true` 观察生活推演，同时关闭主动开口；确认活动与频率曲线后，再逐项接通频率和主动对话。

它当前的主动机制以素材、分数、间隔和每日上限为主，尚不等同于本设计要求的“每天预生成并分散安排若干候选时间点”。早晚问候、生活分享和关系维护可以复用，但仍需补充明确的每日时间槽、跨日窗口归属、稳定关系目标和 WebUI 日程观测。

插件对 A_Memorix 的接入是只读，不会替我们维护长期关系档案；生活日记向长期记忆的提升仍属于独立记忆服务。

## 实现边界

优先作为独立插件实现生活轨迹和主动调度，通过公开 SDK 与 Planner、消息发送和关系身份服务连接。长期记忆提升属于独立记忆服务，插件只写入结构化短期日记，避免把调度、人格和记忆耦合成一个模块。

## Maizone 安全联动

部署补丁 `deploy/patches/maizone-life-context-privacy.patch` 在 `life-frequency` 中增加只读公开 API `get_public_life_state`，并让 Maizone 在生成说说时可选读取它。这个 API 只返回活动枚举、活动持续时间、当天活动轨迹和身体数值；不返回场景自由文本、素材、聊天、关系、会话 ID 或其他人的信息。脱敏后的完整生产配置模板保存在 `deploy/config/maizone-safe.example.toml`，部署时必须由稳定关系身份绑定替换 `__TRUSTED_QQ__`，不能把号码提交进仓库。

Maizone 的 `[send] enable_life_context = true` 开启该联动。若 API 不可用，Maizone 直接跳过生活素材，不会降级读取私聊。生产配置还必须保持 `[send] enable_chat_memory = false`，这是私聊保护的硬边界，而不是仅依赖提示词。

当前生产策略是自动发说说开启、每天命中概率 `0.3`，在 `08:00` 和 `20:00` 两个候选时间附近随机浮动 `60` 分钟。该配置表示每天在候选调度中抽取，不保证每天都会发。自动浏览每 `180` 分钟一次，只允许稳定关系身份绑定的可信 QQ；点赞概率 `0.3`、评论概率 `0.1`。自动回复评论关闭，避免在没有可靠评论者授权过滤时与其他账号自动对话。

所有发送、读取和自动读取权限都使用白名单。真实 QQ 号只从部署实例的稳定关系身份绑定读取，仓库源码、补丁和通用配置不得包含真实号码。
