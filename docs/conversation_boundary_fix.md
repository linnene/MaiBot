# 对话身份与发送边界修复

日期：2026-10-23，Asia/Shanghai。独立修复，不更改私人配置，不删除记忆，不调整人设正文。

## 已确认的问题

- 普通 reply 允许把机器人的刚发消息当目标，发送后又回到 Planner，形成自我补充循环。
- harness v2 完全丢弃 reply_reference，连纠正事件归属、停止话题的意图也无法传给 Replyer。
- 自身历史重建时丢失原始时间；自身锚点的作者还可能被误作关系校验对象。
- 启发式记忆注入只保留正文，省略已有来源与事件时间。

## 修改

- 普通发送拒绝自身目标，成功回复或拦截后结束当前工具循环；一次回复内部仍可分段及附带图片、表情。
- 在生成之前记录本次用户输入标识，仅成功发送才更新已消费标识。生成期间的新消息不会因随后写入的 bot 发言被误判为已回复。
- 主动权限仅取宿主当前任务，模型参数不能伪造；主动发送后同样结束本轮循环。
- 只传递长度受工具合同限制的会话意图，不回传 Planner 全文。该意图不是回复草稿。
- 自身历史使用 assistant role 与 self_message 标记，保留原时间。事件归属依据原句主体，不简单等同于发言者。
- 自身锚点的关系校验从真实用户历史解析，不从机器人自身推导关系。
- 召回注明已有来源、类型和事件时间；缺失主体标记 unknown，不根据参与者列表猜测。

## 验证与边界

合成用例覆盖自我目标、无新输入重复发送、新输入恢复、生成期间新输入、可信主动入口、双方身份、自身日程、原始时间和记忆来源。未调用外部模型回放私人对话。

固定瘦身测试复跑仍保留已记录的 14 项存量失败，没有通过跳过制造全绿。测试集合会随新增回归用例增加，不能直接把测试总数增长当效果提升。

这些是执行与上下文的工程约束，不是自然度或记忆准确率的量化证明。既有错误对话和旧摘要没有删除或重写，仍可能影响生成，需要观察新对话并按证据纠正。

## 部署纪律

部署前对比目标文件指纹并备份，只同步本次修改。macOS 打包使用 COPYFILE_DISABLE=1 与 tar --no-xattrs，避免 AppleDouble 隐藏文件被当作提示词。部署后检查本次 systemd invocation、WebUI、适配器及向量通道，不能仅凭 systemctl start 返回成功就宣称服务健康。
