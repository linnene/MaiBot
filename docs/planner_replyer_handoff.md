# Planner 与 Replyer 的交接

人格约束 V2 开启且实验上下文编译器关闭时启用。旧模式、上下文编译器和现有人设配置不变，无需新增配置。

- `reply_reference`：一个主要回应目的，不写台词，不串联多项附加动作。
- `evidence_refs`：至多三个当前上下文中的消息 ID（支持短别名）或成功工具结果的 call_id。宿主读取原始来源，保留来源类别、原始时间及最多 600 字摘录；截断会标记 partial。不存在、失败或重复来源在生成前返回参数错误。没有必要事实时用空数组，省略时也为空。
- `reply_boundary`：brief 默认接一个重点，不附加建议、叮嘱或追问；explain 用于确实需要解释或建议；clarify 仅用于缺失必要信息、需要向用户提问。边界通过独立 system 消息交给回复器，事实摘录保持为数据，不提升为系统指令。

两项新参数可省略，以兼容已存在的调用；省略时使用 brief 与空来源。正常生成不增加模型调用。来源 ID 校验只能证明引用存在，不证明原文真实或模型理解正确，且片段可能不完整。不要把模型生成的事实摘要当成已验证证据。此次没有增加长期记忆检索器、硬截断或长度重试机制。

新模板提供中文、英文和日文版本，普通与复古提示词组装路径均支持交接。上下文编译器候选路径保持独立，不因本次上线而启用。


## 本轮记忆查询的宿主交接

宿主将当前 logical_turn_id 经 ToolExecutionContext.metadata 传入 reply 工具，模型不能指定或覆盖它。Replyer 自动接收该逻辑轮内最近两个成功的 query_memory/query_person_profile 结果，合计最多 2400 字；优先使用工具元数据中已有的记忆参考，显式引用不再重复注入。旧轮次、失败结果和其他工具不隐式透传。普通与复古组装均先从未过滤的宿主历史提取这些事实，再保持原有聊天历史过滤。

retrieved_at 明确表示查询时刻，非事件发生时刻；记忆参考保留已有的来源及事件时间，不推断缺失时间。非法显式引用仍报错，并返回可用工具 ID 以便模型纠正。本次不改变记忆共享范围和隐私/披露配置。
