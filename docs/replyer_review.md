# Replyer 结构化再审

当 Planner 的当前回复意图与实际说话人、事件归属、时间或证据冲突时，Replyer 可调用内部函数 `request_reply_review`，将原因、证据消息编号和短说明作为工具结果退回 Planner。它不把内部反馈添加成用户消息，也不解析聊天正文中的 `<reject>` 等标记。

配置入口：`experimental.replyer_review = true`，默认关闭。需要回复模型支持原生函数调用。普通回复沿用原来的风格、长度要求和发送流程，不额外调用模型；启用后会增加一个工具定义和一条短执行约定。

宿主按最新真实用户输入（主动轮则按宿主任务 ID）计数：第一次再审允许 Planner 改变意图后重新生成，第二次再审结束本轮，后续同一输入的调用在生成前被拦截。原生调用同时附带的正文也不发送。收到新输入后重新计数。内部生成和原始诊断不写入 QQ 聊天。

这是一条纠错通道，不等于自动证明回复正确。模型仍可能漏用工具。合成测试应覆盖普通短答、说话人/事件归属冲突、过时上下文、错误工具参数、连续退回、发送前拦截及新输入恢复；自然度与长期稳定性需要另行观察。

回退：关闭该开关并重新载入配置即可停止暴露再审工具与执行约定。源代码部署仍需保存服务器实际文件的独立快照，不能用整个本地分支覆盖有未提交修改的服务器。
