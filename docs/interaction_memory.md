# 对话事项与主动互动策略

这是现有人设 harness 和 A_Memorix 上方的可选使用层。长期人物事实、事件与向量仍留在原记忆库；新的工作状态保存于实例 `data/interaction-memory/state.db`，不改动原数据库结构。

## 开关与职责

主配置 `interaction_memory.mode`：

- `off`：不维护或注入新工作状态。若生活插件仍开启委托，主动请求会被拒绝；恢复旧调度需同时关闭委托。
- `shadow`：记录新状态和候选判断，但不替换旧调度的目的，不注入新事项。生活插件委托应关闭。
- `active`：使用新事项背景和主动决策。生活插件 `proactive.delegate_interaction_policy=true` 后由宿主决定冷却与候选，插件保留休息、免打扰和用户每日硬上限。

只处理系统已配置可信身份绑定的私聊对象。群聊权限及私聊内容的披露规则保持原样，不因新策略扩大范围。账号与名字均从运行配置读取，无个人 ID 写入实现。

同一发送入口继续使用已有的 Mai_life → 宿主主动任务 → Planner → Replyer → 平台回执链。没有新增第二个发送定时器。开启委托时停止旧连续话题整理和注入；关闭委托即可重新启用旧路径。生活模拟、重要日期、天气、创作和联网见闻继续运行。

## 事项与证据

工作状态记录当前联系时间、用户明确结束/忙碌状态、未回应次数及事项列表。事项状态为 open/asked/done/cancelled/uncertain/expired。

新用户消息异步触发有界整理；普通闲聊不逐条调用模型。模型操作必须引用实际用户消息 ID 和逐字原话，角色自己的日程不能创建用户事项；旧版本的提取结果不能覆盖更新的用户输入。重复确认同一事件不重复建项。

时间保留原消息时间、明确事件时刻或仅明确日期、回访窗口。相对日期按原消息所属日期校验。仅明确日期时，默认选择该日期结束后次日上午的回访窗口，不把窗口当成事件发生时间；不确定日期的事项不会主动触发。未来事项最多一年，正文原话保留 30 天，事项证据随事项保存。

此模块不是精确提醒/闹钟工具。回访仍受免打扰、休息、冷却与 Planner 判断限制；重要提醒应使用专用任务工具。

## 日常使用与主动选择

日常提示只提供与当前话题相关的少量事项，不因为有待办就强行提及。Planner 和 Replyer 共享同一来源标记，人设和篇幅要求继续沿用原 harness。

主动选择优先检查到期且未问过的事项；其他来源包括早晚节奏、重要日期、外部见闻、与此前用户话题相关的兴趣和独立生活。相关长期记忆复用原搜索服务，并使用短期缓存，不复制为第二份权威人物事实。

默认配置：冷却至少 90 分钟；用户发言后至少 45 分钟；未获回应时冷却延长，连续两次未回应后退让；每日软预算按日期/用户稳定选择 2–4 次，不要求发满；硬上限 7，且不能超过原用户配额；普通生活分享默认每天最多一次；同一话题冷却 48 小时。重要日期和有依据的事项回访可以越过软预算，但不越过硬限制。

候选有短期原子租约，防止并发重复安排。平台确认发送前不扣额度、不标记事项已问；发送后关联宿主任务 ID 做幂等结算。观察期旧策略真正发送的消息单独记录，不把影子提案误算成实际消息。

## 观测与纠正

通过已登录的 WebUI 打开 `/api/webui/memory/interaction-panel`。页面使用原访问认证，可查看原话、来源和事项时间，修改状态或回访时间，并查看最近候选选择/拒绝和写入失败原因。

接口：

- `GET /api/webui/memory/interaction`
- `PATCH /api/webui/memory/interaction/items/{item_id}`，body 包含 status 和可选 due_at（Unix 秒）
- `GET /api/webui/memory/interaction-panel`

页面纠正只作用于工作事项，不会篡改长期记忆原文。长期事实仍使用现有记忆页面纠正。

## 写入可靠性与范围

启用时，人物事实写回改为检查用户证据是否有内容，避免简短的“嗯嗯/好的”机器人回复压掉用户的真实偏好。摘要流程的成功、空增量和失败进入独立审计；失败不会推进原摘要检查点。图片证据提示明确禁止把相对时间当消息 ID；原来的完整证据验证继续保留，没有通过删除验证来制造成功。

模型仍可能漏提取、误判主题或生成无效证据；这些失败应能被看见，不代表已经保证语义完全准确。当前不批量重新处理历史聊天，也不自动修复所有旧事实。模型调用失败或重启时的未完成整理，可能需要用户再次提及或在页面纠正；未来可进一步加入持久提取队列。

## 回退

正常回退关闭新策略并关闭生活插件委托，保留新增聊天、长期记忆及独立工作状态。需要回退源码时，使用实际服务器部署清单与逐文件备份，不能直接用本地 Git 覆盖线上既有差异。

此层不修改旧聊天、向量和生活插件数据库 schema；旧路径不读取独立工作库。禁止为了回退策略直接恢复整份旧数据目录。上线记录应包含源码哈希、配置差异、验证结果及当前回退脚本。
